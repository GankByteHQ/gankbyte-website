PROJECT STANDARD

Make the
useful version.

A good proposal names the problem, target users, first playable or testable version, technology, licence, risks, and what help is needed.

  1. Scope - Keep the first version small enough to test.
  2. Proof - Link a build, example, screenshot, or reproducible description.
  3. Ownership - Explain what you own and which third-party licences apply.
  4. Review - GankByte may ask for changes before a project is showcased.
