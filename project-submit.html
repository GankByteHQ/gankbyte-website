DEVELOPERS // SUBMIT

Bring a small idea.
Make it testable.

Use this route for a new game, tool, Lua experiment, legal resource, or community project. Start with the smallest useful version and show what people can try.

Open project proposal ↗View current projects ↗
01 // Brief

Explain the useful version

Name the people it helps, the problem it solves, and the smallest playable or testable first version. A good idea should be understandable without a pitch deck.

02 // Proof

Show what exists

Link a build, example, screenshot, public repository, or reproducible description. If nothing exists yet, describe the first proof you will make.

03 // Ownership

Be clear about rights

State what you own and identify third-party code, art, audio, frameworks, game platforms, and licences. Do not submit copied game assets or private files.

04 // Help

Say what you need

Tell GankByte whether you need testers, code review, design feedback, documentation help, or a place to showcase the finished work.

REVIEW PATH

Clear stages.
No mystery.

Submissions are tracked through GitHub so the scope, ownership, and status stay visible.

  1. Received - The submission is waiting for triage.
  2. Needs information - Scope, proof, ownership, or licence details need clarification.
  3. Accepted - The project fits the GankByte community and has a clear next step.
  4. Building - A public repository, branch, or playable proof exists.
  5. Showcase candidate - The project is documented, testable, and ready for the project board.
  6. Closed - The submission is declined or complete without a current showcase.
